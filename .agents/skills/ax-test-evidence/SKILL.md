# AX 테스트 증거

문서 유형 · 저장소 테스트 스킬\
상태 · 적용 중\
갱신일 · 2026-11-11\
관련 요구사항과 문서 · [PRD](../../../docs/prd/product.md), [API 계약](../../../docs/api/contract.md), [개발 워크플로](../../../.agent/workflows/development.md), [결과 예시](../../../docs/test/000_example.md)

1. PRD의 수용 기준과 API의 공개 계약으로 기대값을 먼저 정한다. 구현 출력에서 기대값을 복사하지 않는다. 변경과 관련된 정상·실패·경계·회귀 케이스를 고르고 필수 기준을 모두 연결한다.
2. 공개 동작을 검증할 실행 명령 또는 UI 조작 순서, 데이터 준비, 환경과 버전을 기록한다. 종료 코드, 관찰한 값, 로그 위치나 화면 캡처를 증거로 남긴다. 기준 커밋과 실제 검증한 변경 범위(미추적 파일 포함)를 함께 적는다.
3. assertion이 실제 사용자 동작이나 계약의 출력을 확인하는지 살핀다. skip이나 잘못된 테스트 탐색, 과도한 Mock, 빈 assertion, 실제값을 복사한 기대값을 확인한다. 적합한 경우 격리 환경의 이전 결함 버전 또는 통제된 잘못된 입력으로 실패를 재현한다. 공유 작업 트리의 제품 코드를 고의로 깨뜨리거나 실패를 숨기기 위해 기대값을 완화하거나 테스트를 삭제하지 않는다.
4. 실행 기록에 아래 열을 사용한다. 미실행은 사유와 막힌 기준을 적는다. 재실행·정정에는 [공통 번호 규칙](../../../.agent/standards.md)에 따라 새 기록을 만들고 이전 결과를 연결한다. 기존 `docs/test/` 파일은 수정, 덮어쓰기, 이름 변경, 삭제를 금지한다.
