# Title · ADR-000 · 문서 북마크의 중복 저장 방지

문서 유형 · ADR (Example)\
갱신일 · 2026-11-25\
관련 요구사항과 문서 · EX-BMK-001 AC2, [PRD](../prd/product.md), [API 계약](../api/contract.md), [구현 명세](../implementation/000_example.md)

## Status

Proposed

## Context

사용자가 두 탭에서 같은 문서를 저장하거나 응답을 받지 못해 재시도하면 저장 요청이 겹칠 수 있다. EX-BMK-001 AC2에 따라 이때도 북마크는 하나만 남아야 한다.

## Decision

데이터베이스에서 사용자와 문서의 조합에 유일성 제약을 둔다. 북마크를 원자적으로 삽입하고 이미 같은 조합이 있으면 동일한 성공 응답을 반환한다. 삽입 전에 조회만 하면 두 요청이 모두 기존 북마크가 없다고 판단할 수 있다. 저장 버튼을 잠그는 방법은 현재 탭에만 효과가 있다.

## Consequence

재시도하거나 동시에 저장해도 북마크는 하나만 남는다. 배포 시 테이블과 유일성 제약을 추가하는 마이그레이션이 필요하다. 문서 상세 화면의 기존 동작과 접근 권한 검사는 유지한다.

## Governance

코드 리뷰에서 리뷰어는 마이그레이션이 사용자와 문서 조합의 유일성을 강제하는지, 저장 연산이 원자적으로 삽입하는지 확인한다. 테스트 단계에서 테스터는 동일한 조합으로 저장 요청을 동시에 두 번 보내 두 요청이 모두 성공하고 데이터베이스에는 한 행만 남는지 확인한다.
