### Native dialog keyboard observation and test correction

The original strict containment assertion saw Chrome report `document.activeElement === document.body` at the sixteenth Tab traversal around its native dialog/browser-chrome boundary. The next Tab returns inside the modal; no underlying app control receives focus. The corrected assertion allows that BODY sentinel only when the immediately following real Tab returns inside; any outside actionable control or failure to return fails the check. Escape and focus restoration use actual key dispatch, not synthetic DOM events.

This was a test expectation correction, not a product change. An earlier complete run at 14:17:31 UTC passed 73 checks (test hash `db770be2384f93d7d3e90813c85d66e3bed536fbd88990c4a9aa4ea28f177429`; the old results hash was displayed truncated and is not asserted here). The fresh final run above adds clean demo screenshots while keeping the same product. The current `tests/failure.json` is a prior screenshot-harness placement error (attempted to click before page navigation), fixed by moving those steps after load; it is not a product failure and is not the final result.
